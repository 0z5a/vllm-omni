The loader tests call `SenseNovaU1Pipeline.load_weights` on real vLLM QKV
and merged-column layers. The TP tests exercise actual layer constructors
and weight loaders at several degrees. The fixture now uses a temporary
single-rank Gloo FileStore, so it neither needs a GPU nor a fixed TCP port.
The tiny pipeline also supplies the `llm_cfg` fields required by current
main's expert-mapping path.

Ruff check, format and diff whitespace checks pass. These tests use
synthetic weights; they do not establish full-checkpoint coverage, multi-GPU
throughput or an inference speedup.

## Tiny-pipeline E2E on RTX 5090

A temporary 106 MB SenseNova checkpoint used the original model configuration
with two 128-wide Qwen3 layers and randomly initialized weights. It kept the
real `SenseNovaU1Pipeline`, weight loader, FM head, tokenizer route and TP
layers. Each run generated two 64 × 64 images using four denoising steps,
seed 42, CFG 1 and think mode off. The checkpoint was removed after testing.

| Tiny synthetic E2E | TP1 | TP2 | TP2 relative speed |
| --- | ---: | ---: | ---: |
| Successful generated images | 2/2 | 2/2 | N/A — correctness check |
| Second request latency | 83.29 ms | 163.46 ms | 0.510× |
| SHA256 for both outputs | `f3cc103136423a57975750907ebc1d367e2985ac6338976d4d5a439f50323f4a` | Same | N/A |
| Declared VAE modules | 0 | 0 | N/A |

Both processes exited with status 0. The TP2 run exercised the real
multi-GPU pipeline and produced the same serialized image as TP1. Random
weights can yield degenerate pixels, so the hash validates repeatability and
the execution path, not image quality or numerical parity of trained weights.
The host ran unrelated jobs, and the tiny-model latency is not a throughput
claim for the full SenseNova checkpoint, which remains untested here.
