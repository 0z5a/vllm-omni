# Repeated diffusion LoRA updates: Z-Image-Turbo

Measured on one NVIDIA L20 (46 GB), vLLM 0.29.0, BF16, TP1 and eager
execution. Z-Image-Turbo used 256 × 256 images, two denoising steps, seed 42
and two cached synthetic rank-16 adapters targeting 16 real `to_qkv` layers.
Each fresh process ran six warmup switches, 16 same-adapter controls and 40
measured adapter switches. The order was baseline, patch, patch, baseline.

| Arm | Switch + generation median (ms) | Same-adapter median (ms) |
| --- | ---: | ---: |
| Baseline 1 | 215.903 | 175.065 |
| Patch 1 | 209.012 | 175.928 |
| Patch 2 | 211.266 | 171.765 |
| Baseline 2 | 212.985 | 171.726 |
| Geometric mean, baseline → patch | 214.439 → 210.136 | 173.387 → 173.834 |
| Speedup, baseline ÷ patch | **1.020×** | 0.997× |

All base, adapter A and adapter B image hashes matched across the four eager
processes, including adapter reactivation and return to base. The same-adapter
control was effectively unchanged. Each process used 23,066 MiB after
measurement; no slow samples were filtered.

The first compiled comparison used different compiler caches and produced
different image hashes. A later shared-cache comparison matched all three
image hashes exactly; exchanging the original caches exchanged the hashes.
Compiled timing from the first run is excluded. This result measures cached
adapter switching in eager mode; it does not establish a general speedup for
other models, trained adapters or concurrent updates.
