# Structured-output manager compatibility

Current main calls the shared grammar-rejection path from both schedulers.
This PR adds the vLLM 0.29 reasoning-aware fallback there; it does not add a
second generation-scheduler call.

| vLLM 0.29.0 CPU check | Current main | Candidate | Speedup |
| --- | ---: | ---: | ---: |
| `tests/core/sched` | 223 passed, 3 failed | 233 passed, 3 failed | N/A — correctness fix |
| New dispatch and reasoning-boundary cases | Absent | 10 passed | N/A |

The same three timeout/log-capture tests fail on main and candidate in this
0.29.0 environment. No candidate-only scheduler failure remains. Ruff check,
format and diff whitespace checks pass. The repository now pins vLLM 0.30.0,
so this 0.29.0 run validates the fallback and does not replace 0.30 CI.

The current helper was also run end to end with the full Qwen3-VL-8B-Instruct
checkpoint on one RTX 5090. The host has vLLM 0.29.0, so both runs used the
same 0.29-compatible Omni source; the candidate alone received the exact
helper and scheduler dispatch from this PR. Each fresh process made seven
greedy requests for the same JSON schema, with the first request excluded
from timing. Both variants returned `{"ok":true,"count":3}` on all 7/7
requests. Both used GPU 0, eager execution, a 1024-token context and
`gpu_memory_utilization=0.85`.

| Qwen3-VL JSON E2E, warm-request median | Before | After | Relative speed |
| --- | ---: | ---: | ---: |
| Request latency (6 measured requests per variant) | 566.49 ms | 599.04 ms | 0.946× |

These single-process samples were taken on a shared host while independent
jobs used other GPUs. The difference is not evidence of a speed improvement;
this PR fixes API compatibility. The current vLLM 0.30.0 PR head could not
start on the installed 0.29.0 engine, so the result validates the equivalent
fallback path rather than the complete rebased source tree.

The earlier PR head `92be0140` was also tested with a real
MiniCPM-o-4_5 three-stage pipeline on two L20s: four fresh A/P/P/A processes,
seven JSON requests each, first request excluded. All 28 outputs were valid
and identical 11-token JSON.

| Request latency (12 measured requests per variant) | 292.33 ms | 289.85 ms | 1.009× |

That small timing difference on a shared host is not evidence of a useful
