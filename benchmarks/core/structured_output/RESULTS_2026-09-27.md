# Structured-output manager compatibility

Current main calls the shared grammar-rejection path from both schedulers.
This PR adds the vLLM 0.29 reasoning-aware fallback there; it does not add a
second generation-scheduler call.

| vLLM 0.29.0 CPU check | Current main | Candidate | Speedup |
| --- | ---: | ---: | ---: |
| `tests/core/sched` | 223 passed, 3 failed | 233 passed, 3 failed | N/A — correctness fix |
| New dispatch and reasoning-boundary cases | Absent | 10 passed | N/A |

The same three timeout/log-capture tests fail on main and candidate in this
0.29.0 environment. No candidate-only scheduler failure remains. Ruff check,
format and diff whitespace checks pass. The repository now pins vLLM 0.30.0,
so this 0.29.0 run validates the fallback and does not replace 0.30 CI.

The earlier PR head `92be0140` was also tested with a real
MiniCPM-o-4_5 three-stage pipeline on two L20s: four fresh A/P/P/A processes,
seven JSON requests each, first request excluded. All 28 outputs were valid
and identical 11-token JSON.
