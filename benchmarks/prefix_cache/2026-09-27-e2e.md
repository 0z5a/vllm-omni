# Prefix-cache stack: current-head E2E verification (2026-09-27)

This report tests the three incremental cache PR heads: [#8051](https://github.com/vllm-project/vllm-omni/pull/8051) `64f09a5a4079a3eff9a865e428cee97dec70d968`, [#8056](https://github.com/vllm-project/vllm-omni/pull/8056) `5cd1f6c5bbe78c2d221beaaa43e3e9df6851091e`, and [#8066](https://github.com/vllm-project/vllm-omni/pull/8066) `ffdb0df43793b3cc1d527757928a134e0a6c2777`. Each source tree was checked against its PR head before testing. The tests ran in the existing 0z5a Python environment with vLLM 0.29.0 and PyTorch 2.13.0+cu130 on RTX 5090 GPUs. No environment packages were changed.

## Fresh real-model E2E runs

Each cache-off/on arm started a separate Omni engine, generated one cold request plus five measured repeated requests, then exited its workers naturally. The prompt has 960 tokens; greedy decoding emitted 32 tokens per request. E2E timing includes the full `Omni.generate` call. **Speedup = cache-off p50 / cache-on p50**; below 1× is a slowdown. Runs used eager execution, `max_num_seqs=1`, `max_num_batched_tokens=1024`, and the same physical GPUs within each pair.

## Fresh #8066 DCP runtime E2E with random weights

The exact #8066 head also completed a fresh TP=2/DCP=2 full engine run on physical GPUs 1 and 2 with a two-layer Gemma test checkpoint. Both DCP ranks reported a 16/16 physical block layout; the cache-on arm reused 928 of 960 prompt tokens. This verifies runtime wiring, not pretrained-model output quality or production latency. The temporary checkpoint was removed after the pair.

| Checkpoint | Cache-off p50 | Cache-on p50 | Speedup (off/on) | Off/on output parity | Natural exit |
| --- | ---: | ---: | ---: | --- | --- |
| Tiny random Gemma, head dimension 64, 960-token prompt, 32-token output, five measured requests | 0.238 s | 0.331 s | **0.719×** | 6/6 pairs, exact token IDs | both arms |

The test checkpoint `model.safetensors` SHA-256 was `e57b0dfbe351091e94ab7b8e549037e7cda819b7a5b0756dc683ceb39cb68bcf`. The first 32-dimension FlashInfer attempt was rejected during model initialization because that head size is unsupported. A subsequent attempt generated all requests but the default five-second multiworker exit grace expired. The passing pair used `VLLM_WORKER_SHUTDOWN_TIMEOUT_SECONDS=120` and recorded both `complete` markers without terminating workers.

## Evidence and method

The `data/2026-09-27/` JSONL files contain every cold and measured request, including elapsed time, cache-hit tokens, text, and output token IDs. The paired deployment YAML files record the engine settings. `three_pr_e2e.py` is the exact CLI harness; it checks the block-table view at runtime and records a `complete` marker only after natural worker exit. The row medians exclude index 0 (cold), and output parity compares the same index across cache-off/on arms. Pretrained weights were downloaded and SHA-256-checked before serving; the small DCP checkpoint was generated with `make_tiny_gemma_dcp.py`. Each completed model pair's weights were deleted. No model weights are included in this report.
